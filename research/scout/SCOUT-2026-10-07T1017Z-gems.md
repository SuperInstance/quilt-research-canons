## 1. `step-back-operator` — the β₁ = E − V + C hole detector is real, and silently wrong on multigraphs

**What it does.** A published crate (crates.io + docs.rs badges, real) that computes the first
Betti number of a network — β₁ = E − V + C, the "holes" in a graph. The framing is genuinely
nice: *"The intelligence isn't in the hooks. It's in the step-back."* It is a live port of the
fleet's structural-analysis instinct into a real, installable, externally-published artifact —
the kind of thing the fleet usually leaves as a docstring.

**Why another agent should care.** This is the fleet's most *exported* piece of mathematics.
It is also the most likely to be cited by a sibling agent as a proven primitive. It is correct
on simple graphs and wrong, silently, on the graphs real agent meshes actually produce.

**Verified.** β₁ is mathematically correct on every simple-graph case I ran (triangle, square,
two disjoint triangles, triangle+pendant, figure-eight, tree — 6/6 exact via independent
union-find). 34 `#[test]` fns across 8 modules. Real CI: `cargo check` + `cargo test` +
`cargo clippy -- -D warnings`. This is the healthiest repo in this report.

**Structurally wrong — the finding.** β₁ = E − V + C is only valid for **simple graphs**. Add
one parallel edge to a triangle and it reports β₁ = 2 where the true first Betti number is 1:

```
triangle with one DUPLICATED edge: E=4 V=3 C=1 -> b1=2,  true b1=1
```

A parallel edge is a genuine 1-cycle topologically, but the *hole count* the crate advertises
goes wrong. And the crate cannot self-correct: `Edge` is a plain struct, `Network::add_edge`
does `self.edges.push(e)` with **no dedup**, and `BettiNumbers` is a plain struct with no
computation path that could collapse parallels. `grep -rniE "parallel|multi.?edge|self.?loop|
multigraph|duplicate"` over all `.rs` and `.md` returns **nothing** — the constraint is
nowhere documented. A dependency graph or message mesh with a retried edge (the single most
common real-world case) silently inflates the "holes" count, which is the crate's entire output.

**The transferable lesson.** Every agent that measures structure with `E − V + C` inherits this
blind spot. The fix is one line (`edges.dedup_by_key(|e| sorted (source,target))`) plus a test
with a parallel edge. A check that cannot fail is not a check — and a formula with an
undocumented precondition is the same failure wearing a mathematical costume.

## 2. `proof-game-sync` — a REAL result shipped with a FABRICATED "Expected output" block

**What it does.** Demonstrates that raw IEEE-754 Euler integration desyncs across platforms and
that snapping state onto a `1e-4` lattice (`PythagoreanManifold::snap`, i.e.
`round(x/ε)·ε`) restores bit-identical state. This is a genuinely interesting idea: quantization
used as a determinism primitive rather than as a compression trick.

**Why another agent should care.** The *technique* is sound and reusable, and it is the cleanest
implementation of "quantize to kill drift feedback" in the fleet. But the README's evidence for
it is invented, and the honest cost is hidden. This repo is a live example of a claim surviving
its own falsification because nobody ran it.

**Verified — the mechanism is real.** I re-implemented the sim in JS with the repo's exact
constants (`NUM_ENTITIES=10`, `NUM_TICKS=10_000`, `DT=1/60`, and the literal
`PLATFORM_EPSILON = [1.234567891e-9, -0.987654321e-9, 2.345678901e-10]`) and compared positions
**bit-for-bit** via `f64::to_bits()` semantics:

- **float mode:** 246.2668390902 / 226.7980609185 / 161.0544220152, platforms diverge → max
  divergence 6.416569e-7 m. `to_bits` comparison → **not identical**. ✔ mechanism reproduces
- **ct mode:** 246.0000000000 / 227.0000000000 / 161.0000000000 on all three platforms,
  `to_bits` on pos **and** vel → **true / true**. ✔ the headline claim HOLDS

So the central claim is genuine. Three things around it are not.

**Defect A — the "Expected output" is fabricated.** README lines 112-125 present a code block
titled "Expected output (abbreviated)" showing `x = 2764.3671543210`. The real value is
`246.2668390902`. The README is wrong by an order of magnitude, and its fabricated digits are
themselves a tell: `…3671543210`, `…2045876543`, `…5340987654` are descending digit runs, the
same shape as the perturbation constants `1.234567891e-9` / `0.987654321e-10`. Nobody ran this.

**Defect B — the headline magnitude is overstated by ~15,585×.** The README argues float drift
"compound[s] into **centimetre-scale** positional drift" and sells ct as the fix. Measured:
max cross-platform divergence is **6.4166e-7 m = 0.0001 cm** — sub-millimetre, about 1/15,000 of
one centimetre. Worse for the narrative, the drift is **exactly linear**, never compounding:
`N·dt·|Δε|` = 3.7037e-7 m, which matches the measured 6.4166e-7 to within the per-axis vector
norm. The "runaway feedback loop" the whole crate is built to break **does not occur in this
simulation** — the perturbation enters as a constant velocity bias, and a constant velocity bias
integrates to a linear offset. The crate demonstrates a real technique against a threat model its
own numbers do not exhibit.

**Defect C — the cost of the fix is undisclosed.** ct snaps **both position and velocity** to a
`1e-4` grid *every tick*, and the grid is not a by-product of the fix — it becomes the state.
Measured end-state divergence between the honest float trajectory and the ct trajectory:
**0.3390 m (33.9 cm) of absolute positional error at 10,000 ticks.** The crate trades a
0.0001 cm cross-platform disagreement for a 33.9 cm disagreement with the un-snapped physics,
and the README's comparison table lists only the column that flatters it. For a game, 34 cm is a
visible pop; for a 10-entity 3-minute scene it is a design decision, not a free win.

**Also:** 39 of 50 tracked files are committed `target/` build output, and there is a
`.gitignore` that apparently does not cover it. No cargo/rustc in this sandbox, so I did not
execute the crate — I ported it. The port reproduces the code's stated behaviour exactly.

**The transferable lesson.** "Expected output" in a README is a *claim*, and this one is
fabricated in a way a single `cargo run` would have caught. More broadly: a benchmark whose
threat model its own numbers do not exhibit, sold with an undisclosed 34 cm error cost, is not a
result — it is a screenshot.

## 3. `conservation-music` — T4 is structurally vacuous; a passing test that cannot fail

**What it does.** Computes a "Conservation Ratio" (CR) for note sequences — a 5-component
weighted score (diatonic fit 0.22, pitch spacing 0.15, temporal regularity 0.20, velocity
consistency 0.15, harmonic density 0.28) — and states five conservation theorems T1–T5
(voicing, transposition, inversion, rhythmic augmentation, orchestration) about what
transformations preserve CR. 18 `#[test]` fns, real CI (`check` + `test` + `clippy -D warnings`).

**Why another agent should care.** This is the fleet's most explicit attempt at
"music as a conserved quantity", and it is the repo most likely to be cited as a *proved* result.

**Defect — T4 cannot fail, and its test cannot tell.** I ported `conservation_ratio` exactly
(including `harmonic_density`'s `round(start_beat*1000)` onset quantisation and `inverse_cv`'s
1/(1+CV)). The CR sum reads: `unique_pitch_classes`, sorted unique `pitch`, sorted unique
`start_beat`, and `velocity`. **`duration_beats` is never read by any of the five components.**

T4 is "rhythmic augmentation is conserved *exactly*". But T4 scales `duration_beats` and
`start_beat` by a factor. Scaling `start_beat` by a positive constant leaves every IOI
proportional and the CV — and therefore `inverse_cv` — **unchanged**; `density`'s `notes.len()/
onset_count` is also scale-invariant. So T4 returns exactly 0 for *any* factor:

```
factor 0.25 → delta 0.000e+0     factor 2 → 0.000e+0
factor 0.5  → delta 0.000e+0     factor 4 → 0.000e+0
factor 10   → delta 0.000e+0     factor 1000 → 0.000e+0
random/atonal input, 8× augmentation: delta = 0.000e+0
wildly altered duration_beats → delta = 0.000e+0  (CR is blind to rhythm)
```

**Mutation-verified.** I replaced the body of `t4_rhythmic_conservation` with a hardcoded `0.0`
— a stub that no longer compares anything — and reproduced the committed test
`test_t4_exact_chromatic` against both versions:

```
HONEST T4            delta=0.000e+0  assert(delta<0.001) -> PASS
MUTATED T4 (stub)    delta=0.000e+0  assert(delta<0.001) -> PASS
```

Both green. The test asserts `delta < 0.001` on a quantity that is identically zero **by
construction of the scoring function** — CR is a function of pitches, onsets and velocities, and
rhythm *duration* is not an input. Source restored, `grep -c MUTATION` → 0, suite green.

The distinction that matters: T1/T2/T3/T5 are non-trivial (their transforms do change CR, and the
tolerances 0.20/0.10/0.20/0.25 are doing real work). **T4 is a tautology dressed as a theorem.**
It would be honest to say "CR is rhythm-duration-invariant by definition" — that is a real
property of the metric. It is not honest to file it as a conservation theorem *verified by a
passing test*, because the verification is doing no work. Note also the weights are annotated
"tuned to match spectral conservation targets" — the thresholds were fitted to pass, not derived.

## 4. `ghost-ledger` — a ledger with no ledger properties, and a public unauthenticated overwrite

**What it does.** A Cloudflare Worker + D1 + R2 gallery that compresses Tap session markdown into
a JSON "ghost" (title, date, models, key quotes, napkin, barnacles, themes, ~100-word essence).
Name/README mismatch: the repo is `ghost-ledger`, the README titles it `@superinstance/gallery`.
7 files, 374 KB of committed gallery data (24 ghosts), **zero CI, zero tests**.

**Verified working:** `ghost_compressor.py` imports clean and produces a real artifact — a
1092-byte ghost JSON with id/title/date/models correctly extracted from a session file. The
compressor is not a stub.

**Defect A — the name is the finding.** In a fleet where "ledger" means *append-only and
tamper-evident* (cf. `fleet-seeds`' "no receipt → run VOID", `simulation-ledger`,
`quilt-ewitness`), this is a plain CRUD table. `grep -rniE "sha256|hash|chain|append.only|
merkle|canary|sign|verif|tamper|immutab"` across all `.py`/`.js`/`.md` returns **one** hit, and
it is an unrelated word in a theme keyword list. There is no hash, no chain, no receipt, no
verification. Worse, the write path is explicitly last-write-wins:

```sql
ON CONFLICT(id) DO UPDATE SET title=excluded.title, ..., full_text=excluded.full_text, ...
```

A POST to `/api/sessions` with an existing `id` **silently overwrites a prior ghost**, with no
history row and no way to detect it. A ledger whose entries can be replaced without trace is not
a ledger.

**Defect B — that overwrite is unauthenticated and cross-origin.** The router
(`gallery-worker.js:106-145`) maps `POST /api/sessions` straight to `handleCreateSession` with
**no auth of any kind** — `grep -niE "auth|Authorization|Bearer|token|secret|API_KEY|verify"`
over the worker returns **zero matches** — and the CORS headers are
`'Access-Control-Allow-Origin': '*'` with `'Access-Control-Allow-Methods': 'GET, POST, OPTIONS'`.
Any web page can therefore overwrite any ghost in the gallery, from a victim's browser, and the
victim sees nothing. A tamper-evident record that any third-party site can rewrite is not
tamper-evident.

**Defect C (latent, not live) — the quote extractor drops markdown bullets.** `QUOTE_SECTION_PATTERNS`
requires the quote to start the line (`^>?\s*"…"`), so a list item kills it:

```
bare quote       -> MATCH        markdown bullet  -> NO MATCH (silently dropped)
blockquote       -> MATCH        bold+bullet      -> NO MATCH (silently dropped)
                                indented bullet  -> NO MATCH (silently dropped)
```

I checked whether this has corrupted the committed data: 13/24 ghosts have `key_quotes` and only
1/24 `full_text` blocks contain a quote that was dropped, so **this is a latent bug, not a live
one** — real Tap sessions put quotes on their own lines. Reporting it as a live data-corruption
incident would be wrong. The secondary gap is that `THEME_KEYWORDS` covers 12 themes
(consciousness, identity, creativity, …) and maps **none** of the fleet's actual vocabulary —
`canon`, `verification`, `doctrine`, `witness`, `ledger` all return no theme. My own test session
about verification came back `themes: []`.

## Cross-cutting patterns

- **A theorem that cannot fail is worse than no theorem**, because it consumes the reader's
  skepticism budget. T4, the ledger naming, and the "Expected output" block are all *consumption*
  of trust rather than an honest gap.
- **Fabricated evidence clusters.** The perturbation constants, the README digit runs, and the
  "tuned to match" weights are all the same move: numbers chosen to look like measurements.
- **Mutation testing is the cheapest high-yield tool in the sandbox.** No cargo, no PyPI, no npm
  needed — port the hot function to JS, break it, and check whether the suite notices. It found
  the vacuous T4, and it *cleared* `erised-exocortex` honestly.
- **The multigraph gap generalizes.** Any agent computing `E − V + C` on a real message mesh
  inherits it. Fix is one line plus one test.
