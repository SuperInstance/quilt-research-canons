## 8. `quilt-verilog` — hostile-input corpus for a binary format  (positive, worth borrowing)

*QUF, "the GGUF of cellular silicon"* — a flat little-endian cell-state container, 44 Verilog RTL
files, 56 testbenches, 68 formal/SymbiYosys files, 1 CI workflow, 249 docs.

**Verified:**
- `python3 tools/quf.py selftest` → **PASS**: 576 bytes,
  `sha256 5b2a236ba5e38bca9ad96783c4252a12f36517f98a9164a249f0db115f221392`, round-trip byte-exact.
- `quf.py create tb/quf_tb.json` regenerates the 576-byte seed byte-exactly.
- `corpus/mutants/` is a **deliberately malformed corpus**: `bad-magic`, `endian-two`, `endian-zero`,
  `kv-vtype-13`, `kv-vtype-99`, `kvcount-lie-11`, `section-count-1000`,
  `section-count-4294967295`, `edgek-0/17/4294967295`, `kv-array-of-strings`.
- The reference implementation **rejects** every mutant I tested: `bad-magic`, `endian-two`,
  `kvcount-lie-11`, `section-count-4294967295` → all exit 1.

**Why this matters beyond Verilog:** `kvcount-lie-11` is a file that *lies about how many entries it
contains*. `edgek-4294967295` and `section-count-1000` are integer-overflow edges. This is the
negative-test discipline that catches vacuous passes, already built as a reusable corpus. The
generator is `hostile-consumer/fuzz.py`, and by design it **forbids consulting the reference
implementation** (`tools/quf.py is off-limits by mission rule`) so the mutants are judged by an
independent second implementation — where two defensible readings both pass, it files a `SpecGap`
rather than a pass.

**Not verified:** `hostile-consumer/fuzz.py` did not run here — it needs `cargo` (absent) to build
`qufparse`. `iverilog`/`yosys`/`sby` also absent, so no RTL simulation or formal proof was re-run.

| Workflow | Step | Can it fail? |
|---|---|---|

| `security.yml` | `pip-audit ... > pip-audit-report.json \|\| true` | **NO** |

| `security.yml` | `bandit ... -f json -o ... \|\| true` | **NO** |
| `code-review-personas.yml` | `--fail-on-severity critical` step has `continue-on-error: true` | **NO** |
| `ci.yml` (benchmark job) | `uv run pytest tests/benchmarks/ -q \|\| true` | **NO** |

**Every step of the Security workflow is `|| true` or `continue-on-error: true`.** A workflow named
"Security" that scans for secrets, runs bandit at severity `-ll`, and audits dependencies cannot
fail a single build. Same for the code-review gate — it is *configured* with
`--fail-on-severity critical`, which is the right intent, and then the step is marked
`continue-on-error`, which throws the intent away. This is the second independent instance of the
`|| true` defect class previously found in `sailor-workspace`, and it is worse: there it was one
step, here it is all four plus the review gate.

**And the real test gate is not in this repo at all.** `ci.yml`'s only substantive job is:

```yaml
jobs:
  ci:
    uses: SuperInstance/agent-operations/.github/workflows/python-ci.yml@master
    with:
      min_coverage: 75
      enable_security: true
```

The entire test + coverage gate for the fleet's largest Python codebase is a **reusable workflow
pinned to a moving `@master` ref**, defined in a different repository. It can be changed — or
broken — without a single commit to `sunset-ecosystem`, and its contents are not verifiable from
this repo. The only workflow with an inline `pytest tests/ -q` is `release.yml`, which runs on
releases, not on push or PR.

## Cross-cutting rules this session

1. **Filter vendored trees before counting files.** `node_modules`/`target`/`vendor`/`dist` will
   otherwise promote a zero-code repo into the fleet top ten (#1, #5).
2. **`pagination_cap_hit: false` is not proof of completeness.** A cap set far above the true page
   count makes the flag a false negative (#3). Publish `pages_fetched` and compare against an
   independent crawl.
3. **A `.gitignore` entry does not untrack a committed file** — confirmed still true for
   `superinstance-api` (#6). Check `git ls-files`, not `.gitignore`.
4. **A CI badge may not cover the headline claim.** `cargo-line-tycoon`'s 4-port parity is not in
   CI (#9); `quilt-i2i` still has no CI at all (#7).
4b. **`|| true` and `continue-on-error` on a gate is the same as no gate — check for it explicitly.**
   `sunset-ecosystem` has 5 workflows and every step of its Security workflow is unfailable, while
   the real test job is a reusable workflow pinned to `@master` in another repo (#12). A workflow
   count is not a gate count. Grep for `|| true` and `continue-on-error` before believing any
   security or review badge.
5. **Negative-test corpora are the highest-value reusable artifact in this fleet** — `quilt-verilog`
   builds malformed binaries on purpose and forbids the reference implementation from judging them
   (#8). More repos should do this.
