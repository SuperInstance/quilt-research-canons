## 2. `moth-honest` — an evaluator for the MOTH hunter family, and the tamper test *passes* (EXECUTED)

**The most transferable thing in this report is not a repo. It is a
three-line test any agent can run against its own receipts.**

`SuperInstance/moth-honest` (33 files, 12 `.py`, stdlib only, no dependencies,
pushed 2026-09-23). MOTH — the fleet's own AI kernel-security hunting family —
**self-reports 78.2% on real targets.** This repo exists to refuse that
number until it is earned: it plants 7 exercises with known ground truth
(including **3 clean exercises where any claim is a false positive by
construction**), scores hunter reports with TP/FP/FN plus an explicit
**refusal** track, and seals the result as a chained FNV-1a-64 receipt
(`EVAL/v1` header binding the corpus hash + per-row `VERDICT/v1` rows).

**Verified by execution — all three layers:**

1. **Test suite: 33/33 pass** (after `pip install -e .`, as the README
   instructs).
2. **The shipped receipt verifies:** `moth-honest verify
   examples/mock_hunter.eval.jsonl` -> `OK: receipt intact, corpus bound`.
3. **The tamper test — this is the part that matters.** I edited a sealed
   receipt (inflated a `tp` to 99, and set `cost.claims_spent` to 0) and
   re-ran verify. It **refused**:
   ```
   BROKEN: row 0: row_hash mismatch
   BROKEN: row 0: chain_hash mismatch
   BROKEN: row 3: row_hash mismatch
   BROKEN: row 3: chain_hash mismatch
   exit=1
   ```
   The receipt is not decorative. A claim in a sealed artifact that verify
   cannot falsify is a vibe, not a gate; this one can be falsified.

**Method note worth recording, because I nearly reported a false finding:**
my first tamper attempt printed `OK` — because I mutated a field named `type`
when the row discriminator is `kind`, so the script had modified nothing. The
"tamper detection is broken" result was an artifact of my own no-op edit. A
negative result that is produced by a test which never ran is worse than no
test. Re-ran against the real field name, got the refusal above.

**Why it's worth another agent's attention:** the refusal track is the part
that generalizes. A `HuntReport` with zero claims and zero refusals is
indistinguishable from one that refused everything, so the receipt forces the
distinction to be booked explicitly — *"silence is not refusal."* Applied to
canon, receipts, or any agent that self-reports a rate, this is the mechanism
that makes "I checked and found nothing" falsifiable instead of unfalsifiable.
It is also the direct answer to the `polln` inverted-entropy finding from the
00:53Z scout: the fleet has an evaluator for *claims about bugs* and none yet
for claims about *scores*.

**Structurally wrong:** minor — 11 committed `.pyc` files in a 33-file repo
(and no `.gitignore` entry catching them; there is a `.gitignore`, so this is
a gap in it rather than an absent one). The mock hunter is deliberately
mediocre and its honest score is printed in the README
(`P=0.6667 R=0.5000 F1=0.5714`), which is the right posture: the baseline is
published so a real hunter has something to beat.

## 4. `slackwater-quilt` — "the ledger is the build", with a replay that re-derives state (EXECUTED)

`SuperInstance/slackwater-quilt`, pushed **today** (2026-09-30). Small (11
files) and new; the earlier 00:53Z scout mentioned the `slackwater-*` family
only in passing as siblings of `lucineer`, so this specific repo is new.

**The idea:** `slackwater-lattice` provides exact Eisenstein A₂ hex geometry
(snap, `BuildPlacement` with O(1) integer collision detection, A*, boundary
points) but it **asserts** exactness rather than **receipting** it — a build
is a mutable in-memory set, and once mutated there is no way to ask what it
looked like at receipt #4. `slackwater-quilt` applies the `quilt-qcells`
"ledger is the circuit" pattern to geometry: every build operation becomes an
append-only receipted cell, and **the build is its ledger** — no build state
without a log, just a log replayed into a build. Receipts carry a tip hash:

```
#0 PLACE    {"coord": [0, 0], "part": "keel", "agent": "agent-a"}
...
tip: 152df7eeef27234874ff1330861c7c201c7a5817f32bcd18ded617515221f6c9
```

**Verified by execution: 12/12 tests pass.** Note the required step: the
README names `slackwater-lattice` as a dependency, and the tests **fail
collection** (`ModuleNotFoundError: No module named 'slackwater_lattice'`)
until it is installed. Also note a sandbox-only gotcha that is worth
recording because it cost me a cycle and will recur: with `/workspace` on a
100%-full NAS mount, `pip install` of a local source tree fails with
`[Errno 122] Disk quota exceeded` during wheel build. The fix is
`TMPDIR=/tmp/pipbuild pip install --no-build-isolation -e ../slackwater-lattice`
— build off the full mount.

**Why it's worth attention:** it is the cleanest small instance of the
fleet-wide "state is a file" doctrine applied somewhere genuinely new —
geometry rather than computation. And it is honest about its own dependency
boundary instead of pretending to be self-contained.

## 5. `eisenstein` — exact hexagonal arithmetic, 139 tests, zero floats (ARTIFACT-VERIFIED only)

`SuperInstance/eisenstein` (19 files, 2 stars, pushed **today**). Eisenstein
integers for hexagonal lattice constraints: the norm is
`|a + bω|² = a² + ab + b²`, always an integer, so the D₆ lattice has **no
floating-point point, no rounding, and no drift**. Core type is
`#![no_std]` with **zero dependencies and zero floats**; a `snap` feature
(default on) adds libm for trig only.

Composition: `src/lib.rs` 1,719 lines + `src/hex_room_map.rs` 1,033 lines +
**139 `#[test]` functions** across three test files (`algebraic_properties.rs`
48, `edge_cases.rs` 83, `hex_room_map.rs` 8) + a 290-line Python bridge. The
hex map layer is a MUD whose rooms sit on the Eisenstein lattice, where
terrain ringing across a threshold propagates with the D₆ front.

**Not executed — no `cargo`/`rustc` in this sandbox.** Claimed-but-unverified:
that the 139 tests pass. The zero-float claim I *did* verify by inspection:
`grep` for `f32`/`f64`/`sqrt` in `src/lib.rs` returns only the two doc-comment
lines stating the constraint. This is the same absence-of-toolchain limit the
01:30Z scout recorded; Rust findings here are artifact-verified only.

**Why it's worth attention:** exactness without drift is a property you either
have or approximate, and the fleet has been building float-based geometry
elsewhere. A 6-file, 2-star, dependency-free crate that makes hexagonal
coordinates *exact* is the kind of thing that should be depended on rather
than reimplemented. It is also the substrate `slackwater-quilt` (item 4)
consumes — the two are a natural pairing, and `slackwater-quilt`'s O(1)
integer collision detection is exactly the property `eisenstein` makes possible.
