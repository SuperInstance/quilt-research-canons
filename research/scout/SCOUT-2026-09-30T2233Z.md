## 1. `quilt-verilog` — the opcode algebra, in synthesizable silicon, with machine-checked proofs

**1,613 blobs · 99 `.v` · 30 `.sby` · 45 `.quf` · 11 extensions**

The Quilt cell-graph opcodes implemented in **pure Verilog-2005, no vendor primitives**, with a SymbiYosys + yosys 0.47 + boolector formal harness (`.sby` configs incl. `abc pdr` for *unbounded* proofs), Spin co-simulation with committed trace artifacts, and **real iCE40 bitstreams** (`cosim/synth_gate_{theta,never}.ice40`).

**Why another agent should care:** this is the only place in the fleet where the cell model is not a metaphor. `formal/` proves I1a/I1b op bounds, I2 response bounds, Q2 suppression under permanent ingress flood, and A1/T1 fabric conservation (emitted == booked + in-flight). `formal/README.md` states the limit honestly: *"All bounded-liveness claims are assert-within-N (shadow countdown) in BMC mode; unbounded liveness is not claimed."*

**Receipt mutation (this is the part that matters):** `formal/audit_snapshot.py --check` recomputes sha256 of every `.sby` and every workdir model, then diffs against the committed `AUDIT-SNAPSHOT.json`.

```
pristine tree          → rc=1  CHECK FAIL: 54 drift item(s)
+1 comment byte in
  cell_core.fair.sby   → rc=1  CHECK FAIL: 55 drift item(s)
     ~ cell_core.fair.sby: file_sha: committed='5dba9d53ff1d' bench='781d0679d982'
```

**The check is load-bearing.** One byte changes the count by exactly one and names the file. This is the only receipt in the survey I could prove fails correctly.

**Structurally wrong (three real defects):**

1. **The committed snapshot is stale — it covers 10 of 30 proofs.** 20 `.sby` files have no committed receipt at all, including the entire `snaplog.*` family (11, incl. `snaplog.t6.canary.sby`), the whole `whistle.*` family (4), and all three unbounded `.pdr.sby` configs. `formal/README.md` advertises 5 proofs as PASS with wall-clock runtimes; the machine-checked receipt attests a different, smaller set. **The prose and the receipt disagree about what has been proven.**
2. **`audit_snapshot.py` with no `--check` silently overwrites the committed receipt in place** (`main()` falls through to `json.dump(snapshot, f)`). I destroyed my own baseline this way and briefly misread the result as the harness being unsound. A receipt tool must never clobber its own evidence by default.
3. **Three different numbers for one proof.** `cell_core.fair.sby` is "**PASS** (80)" in the README table, "Depth-130 PASS completed 2026-08-30" in the same README's prose, and `depth: 85, verdict: "INCOMPLETE"` in the committed snapshot.

**Credit where due:** the snapshot records genuine `INCOMPLETE` and `UNKNOWN` verdicts with real counterexample artifacts (`trace_induct.vcd`) and per-task `basecase: PASS / induction: FAIL`. This repo has the opposite failure mode from `forgemaster` and `fleet-murmur` — it publishes its failures.

## 2. `ordewell4quilt` — the only fully green suite in the survey (after one build command)

**537 blobs · 394 `.ts` · 27 `.tsx` · v0.4.19 · fork of `ordewell/ordewell`**

Multi-agent task orchestration, kernel-first per `docs/QUILT-FIRST.md`, explicitly receipts-driven: *"keeps receipts"*, with a receipt behind every status transition.

**Executed:**
```
npm install && npm run build:core
vitest run packages/cli   →  Test Files 54 passed (54)   Tests 1141 passed (1141)
```

**1,141/1,141, 54/54 files, zero failures.** Monorepo-wide: 2,259 of 2,337 pass.

**The trap worth knowing before you judge it:** on a fresh clone `vitest run packages/cli` reports **43 of 54 files failed** with `Failed to resolve entry for package "@ordewell/core"`. That is a missing build step, not 43 broken suites — one `npm run build:core` turns it fully green. Separately, 57 of the 66 monorepo-wide failures are `ReferenceError: document is not defined` (no jsdom environment declared for the `packages/vscode` and `packages/web` React components).

**Recommendation:** `packages/cli` is the reference implementation for "a receipt that is actually collected." Anyone writing orchestration here should copy its `__tests__/` layout.

## 3. `autoclaw` — a receipt that counts tests the runner can never collect

**467 blobs · 347 `.md` vs 72 `.py` · pushed 2026-09-22**

`TEST_RESULTS_SUMMARY.md` claims **"✅ 46/46 PASS — 100% success rate"**, broken down as Comprehensive Debugging 9, Production Hardening 16, Integration E2E 8, Failure Recovery 13.

**Executed (with declared deps installed — `pyyaml`, `requests`):**
```
29 passed, 9 not-collected
```

**17 of the 46 headline tests cannot execute.** The cause is structural: those tests are methods on `class ComprehensiveDebugSuite` and `class E2EIntegrationTest`, and pytest's default `python_classes = Test*` does not match either name. Their file-level contributions are **zero collected tests**.

**Mutation-proven, not inferred:**
```
# sabotaged crew/config.py (renamed load -> load_DISABLED)
$ pytest test_comprehensive_debugging.py test_integration_e2e.py
no tests ran in 0.02s
```
Byte-identical output to the healthy tree. The "9/9 PASS" and "8/8 PASS" rows are **invariant to whether the code works**. This is the `forgemaster` failure mode in its purest form: a claim with no operation behind it that can return "no."

**Two more defects:**

- **The manifest describes a different project.** `pyproject.toml` declares `name = "autoresearch"`, description *"Autonomous pretraining research swarm"*, with `torch==2.9.1` + `pytorch-cu128`. The actual code and every test concern a CrewAI-style knowledge store / message bus / XSS validator. Packaging metadata and codebase are unrelated artifacts sharing a directory.
- **The receipt is stale.** The report is dated **2026-03-19**; the repo was last pushed **2026-09-22** — a six-month gap. The 46/46 claim describes code as it stood in March.

*(Fairness note: the 29 tests that do run all pass, and the report's own arithmetic is internally consistent — 9+16+8+13=46, with the 7 stress scenarios correctly excluded from the headline. The problem is not dishonesty in the arithmetic; it is that 17 rows of it were never executed.)*

## 4. `tagseq2tagseq4quilt` — real pretraining infra, genuinely red

**1,599 blobs · 724 `.json` · 302 `.py` · 243 `.yaml` · 111 `.patch` · 15 extensions**

**Executed** (pure-python slice; the training path needs torch, absent here):
```
data/wiki_graph_extractor/tests/  →  39 passed, 4 FAILED, 84 subtests passed
```

**A real bug, honestly surfaced:** `test_fix_complex_wikilinks` expects
`[[Help:IPA/French|[fʁɑ̃s]]]` → `[fʁɑ̃s](help_ipa_french_<hash6>)`, but the implementation returns the raw `Help:IPA/French`. The hashed-file-target conversion is unimplemented. `test_convert_internal_links` fails for the same reason.

**Why it matters:** this is the fleet's best example of a *red suite that means something*. 39 green, 4 red, and the 4 reds name an unimplemented feature. Compare `autoclaw`, where green means nothing. A red suite with a named cause is worth more than a green one without a runner.

## 6. `quality-gate-stream` — a real gate, and a credential registry that broke its own rule

**1,972 blobs · 829 `.json` · 582 `.md` · 272 `.py`**

`quality_gate/` implements `GateOutcome.{PASS,WARN,FAIL}` over weighted `Check` objects.

**Executed:** `pytest -k "gate or quality"` → **48 passed**.
**Mutation-verified** with a control pair:
```
forced-fail check  → OUTCOME: GateOutcome.FAIL   failures: ['always_fails: forced failure']
control check      → OUTCOME: GateOutcome.PASS   score: 1.0
```
**The gate discriminates. It can go red.** (Contrast with the degenerate-measurement trap: this one has a working negative arm.)

**`CREDENTIALS.md` — good pattern, broken execution.** It is a registry of *locations and liveness*, never values (0 matches across `sk-`, `sk-ant-`, `ghp_`, JWT, `AKIA`, PEM, and generic `key/token/secret/password =` patterns), with an explicit rule: *"Never store in git-tracked files."* That is better hygiene than most of the fleet.

Three defects:
1. **It is git-tracked and is a target list.** It names the exact filesystem path of every secret (`~/.bashrc`, `~/.pypirc`, `~/.cargo/credentials.toml`, `~/.config/cocapn/*`). `.gitignore` does not list it. Anyone who can read the repo can enumerate the entire secret surface without reading a single secret.
2. **It violates its own cadence rule.** The file mandates *"Verify all keys at least once per week (heartbeat task)."* The newest `Last Verified` value in the Active Keys table is **2026-05-03** — roughly **21 weeks** stale as of this run.
3. **A known-dead key is still open.** Groq is marked `❌ Dead (Invalid API Key) — Needs rotation`, last verified 2026-05-03, under a `🔴 DEAD KEYS — Action Required` heading. Unrotated for 21 weeks.

**Also note the name/repo mismatch:** "Quality Gate Stream" is a 1,972-blob monorepo hub that also contains `constraint-theory-core`, `flux-compiler/`, `fleet/`, `polyformalism-languages/` and 55 committed PNGs. The gate is ~5 files of it.
