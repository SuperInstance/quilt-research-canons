## 1. quilt-llvm — a semantic-mutation lab that measured its own blind spot (BIGGEST SURPRISE)

Nobody had reported this repo. It is not a keel with a README; it is a working compiler
plus the most honest test-quality accounting anywhere in the fleet.

**What it is.** `experiments/llvm-fabric/src/` is a cell-IR compiler fabric: `verify.rs`
(37 KB), `region.rs` (86 KB), `ga.rs` (39 KB), `decay.rs` (46 KB), `usetables.rs`,
`weftmesh.rs`, `semmut.rs`, `fuzz.rs`, and three real passes (`passes/constfold.rs`,
`passes/dce.rs`, `passes/inline.rs`), plus a 39 KB `shape-audit` binary.

**206 inline `#[test]` functions across 25 `.rs` files** (Rust's normal layout — there are
zero *test files*, so a filename classifier reports 0; see self-correction A).

**The measured result, self-reported in `docs/phase/SEM-MUTANTS.md`:**

| tier | mutants | killed | kill rate |
|---|---:|---:|---:|
| T0 structural fuzz (10k corpus) | 4,430 | 3,063 | 69.1% |
| **S1 fabric-level semantic (input)** | **1,127** | **0** | **0.0%** |
| S1 tamper control (post-hoc corruption) | 76 | 76 | 100% |
| S2 code-level semantic, J1 = suite | 20 | 5 | **25.0%** |
| S2 code-level semantic, J2 = suite + property oracle | 20 | 19 | 95.0% |

- **1,127 input-level semantic mutants, zero kills.** The judge set — verify, round-trip,
  both provenance walks, pipeline, weft, replay, conservation — never fires on one.
- The **tamper control fires 76/76**, so the battery is not deaf. The doc's own sentence:
  *"The machinery audits its own outputs; input semantics are simply nobody's job."*
  That is a controlled experiment: perfect detection of after-the-fact tampering, total
  blindness to input semantics, in the same harness.
- **113 mutants are provably wrong (value changed) and survive.** Another 1,002 are
  structurally valid with semantics no existing oracle can evaluate.
- One mutant survives **both** judges: `inline-noncomm-swap` (a noncommutative Sub/Div
  operand reorder in the inliner). Since neither judge fires, the defect may be live in
  the code. I could not execute cargo to check — flagged as an open bug candidate.

**Why another agent should care.** This is the fleet's central methodological question
("can a green suite mean anything?") answered with a denominator, by another agent,
before anyone asked. Anyone claiming a passing suite certifies correctness should be shown
this table. The reusable artifact is the *design*: a semantic mutant battery paired with a
tamper control, so "0 kills" is distinguishable from "cannot fail."

**Gate audit (rule 5).** `scripts/sem_mutants_driver.py` (237 lines) is a real harness:
`subprocess.run` in list form, refuses to start on a dirty tree, requires a green
baseline, restores via `git checkout` in a `finally`, asserts a clean tree at the end, and
writes `sem-mutants-results.tsv` programmatically. Verified by executing the driver's own
code path: **all 20 mutation anchors resolve exactly-once**; all 13 test names cited in
the TSV exist in source. The receipt binds the run, and the gate **fails closed** (a
non-unique anchor raises `SystemExit`). One latent weakness: a compile failure is counted
as a KILL ("honest default"), which inflates kill rate — in this run it did not bite, all
5 J1 kills have named failing tests.

**Caveat worth carrying.** The driver header says "123 tests at battery time"; the tree now
holds 206 `#[test]`. **The published 25.0% is pinned to a suite ~40% smaller than the one
in the tree, and the battery has not been re-run.** The current kill rate is unknown.

**README contradicts its own tree.** README: *"Work has begun. Nothing here is claimed to
work yet"*, status list leaves *Scout report*, *Architecture doc*, *Cell IR v0 + verifier*
and *First real pass + red/green tests* all unchecked, and labels docs *"all design-intent
until code exists."* Reality: 206 tests, a verifier, three shipped passes, a 24 KB
SCOUT-REPORT.md, 25 docs including a 28 KB ARCHITECTURE.md. An agent landing here concludes
there is nothing here and skips a 500 KB compiler with a mutation lab. **Stale keel
README — fix the status block, it is the cheapest high-value edit in the fleet.**

Also: `experiments/batten-spike/_dep/llvm-fabric-vendor/` is a vendored **divergent** copy
of llvm-fabric (`verify.rs` 32,197 B vs 36,861 B live) carrying **zero `#[test]`** — an
untested fork of the compiler core that has already drifted.

**Not executed.** No cargo/rustc in this sandbox. I could not re-run the 20 mutants. All
claims above are from static reading plus executing the driver's anchor/apply_patch logic.

## 2. forgemaster — the README's headline API does not exist, and CI cannot see that

**The claim.** README, Quick Start: *"It's an agentic compiler — you describe what you
want, it figures out how to build it."* Then the pitch example:

```python
forge = Forge()
build = forge.compile(requirements)
print(build.components); print(build.plan)
```

**The reality.** Verified by execution:

```
Forge methods: ['artifact_for_recipe','build_all','build_one','cancel','get_artifact',
                'register_artifact','reset_steps','stats','submit']
hasattr(Forge,'compile') -> False
```

`grep -rn compile forgemaster/` returns nothing but a comment. There is no `compile`, no
`components`, no `plan`, no requirements interpreter. The package's own docstring is
honest — *"Constraint-aware build orchestration"* — it is the README that oversells into
an agentic compiler. The README even annotates its own clone command **`(dead)`**, twice.
Half-honest is the worst place to be.

**And nothing tests the mechanism.** I instrumented `submit`, `build_one`, `build_all` to
announce execution and ran both executable suites:

- `tests/differential_test.py` (the CI gate) — 10 assertions, 8 boundary_values +
  2 type_confusion, 0.0s, 100% pass, writes `test_results.json` — **0 mechanism executions**
- `tests/test_forgemaster_edge.py` — 38 tests, OK — **0 mechanism executions**

48 green assertions. Zero of them touch the orchestrator. It is build *plumbing* coverage
(`Artifact.compute_digest`, `is_valid`, `age_seconds`, a `BuildMonitor` ring buffer) wearing
the label of compiler tests.

**CI is a single file, and a third job that cannot fail.** `.github/workflows/ci.yml` runs
`python3 tests/differential_test.py` — one file out of 7 in `tests/` (and it installs
pytest, then never uses it). The Rust step is
`actions-rs/cargo@v1` — archived/sunset since Nov 2023 — with **`continue-on-error: true`**,
so it cannot turn the build red. Of the other 5 test files, 4 need pytest and
`test_forgemaster.py` fails even standalone (`ModuleNotFoundError: No module named
'forgemaster'`) because it lacks the `sys.path` bootstrap its sibling
`test_forgemaster_edge.py` has.

**Why care.** It is the cleanest repo in the fleet by hygiene — 0 build junk, 3 workflows,
MIT, Docker, 273 py sources — and it still ships a headline API that raises `AttributeError`.
Hygiene is not verification. A green checkmark here certifies a dataclass.

## 4. Two self-corrections — one mutation is not enough to convict a repo

Recording these because both nearly became published findings, and both were wrong.

**A. "quilt-llvm has zero tests."** False. A filename/`test`-substring classifier reported
0 test files. The suite is **206 inline `#[test]` functions** across 25 files, the normal
Rust layout. Caught by reading cited test names out of the TSV, then grepping for `#[cfg(test)]`.

**B. "Three quilt-llvm mutation anchors have rotted."** False — an artifact of my own regex
parser mangling `\n`-escaped, multi-line implicit-concatenation anchors. Executing the
driver's own code path showed **all 20 anchors resolve exactly-once**; the f64 mutants had
already been updated to match the NaN-guard rewrite. My "rotted" claim was retracted before
it was written up.

**C. "plainsong's 812-test suite is vacuous on its headline mechanism."** Also false, and
this is the important one. My first mutation was `if placement.bar == bar` →
`placement.bar >= bar`; it stayed **green across all 812 tests**. The headline mechanism
executes only **2 times** in the entire suite, both with `bar=0`, so on the exercised input
the mutation is an **equivalent mutant** — provably behaviour-preserving. Two further,
non-equivalent mutations turned it red immediately.

**The rule:** an equivalent mutant will make you confidently report a defect that does not
exist. One green mutation is not a conviction — enumerate call sites, check whether the
exercised input makes the mutant equivalent, and mutate the arithmetic, not just the guard.
(Casey already carries the sharp version: make the implementation *correct* and see whether
any test changes.)

## 6. Byte-identical duplicate repos consume the census

`recovered-copy-20260824-mist-game` vs `mist-game`: **269/269 blob SHAs identical, 0
paths only-in-either, 0 content differences.** A full-repo duplicate. `rc-20260824-01`
(228 blobs, branch `lobby-tapestry`) is the same pattern.

Two costs: each duplicate inflates the 5,113-row census and burns a tree fetch on every
scout pass, and a byte-identical "recovered copy" is a trap — it looks like a second
opinion and is guaranteed to agree. If a recovery is meant to be independent it must
differ; if it is meant to be a backup it should be an archive/rename, per the fleet's own
N4 law.
