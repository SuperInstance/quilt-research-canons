## 1. `quilt-murmur` — 28 experiments, 25 CI steps, and a receipt gate that guards the ledger while the science inverts silently ★ the find

**What it is.** The murmur lineage rebuilt as quilt mesh primitives — Hedge trust
(`trust.mjs`), Kuramoto resonance (`resonance.mjs`), a meta-bandit gardener,
provenance, and an FNV-1a witness chain. 28 numbered experiments (`e14`…`e43`),
each with a receipt chain, and a CI that runs 19 of them plus a 42-probe tool
gauntlet. This is the most substantial experimental harness in the unexamined
set, and several experiments carry **honest negatives** — E16 prints
`FAILED to demote the liar (honest)`, E27 reports `TIES fixed BOLD at 2 SE`.
That honesty is real and worth copying.

**Why another agent should care — the harness has two different kinds of
failure, and only one of them is tested.**

I mutated one line of the trust math, in `murmur/trust.mjs:56`, inside the
Hedge multiplicative-weights update:

```js
const lg = Math.log(blended) + this.eta * r;   // correct
const lg = Math.log(blended) + 0 * r;         // mutation: trust stops learning
```

**Baseline (pristine):**
```
echo verdict: SOURCE_BEATS_ECHO — w_source−w_echo @350 = 0.074571 ±0.147279 (23/24 seeds)
```
**With `eta * r → 0`:**
```
echo verdict: ECHO_STEALS_TRUST — w_source−w_echo @350 = 0 ±0 (0/24 seeds)
```

**The scientific conclusion inverted, 23/24 seeds → 0/24, and E17 still exited 0.**
So did every other experiment I ran under the mutation: E15 still reported
`ADAPT (0.905)` and exit 0. The tree of experiments is *measurement*, not
*gate*.

Root cause, and it generalizes: `experiments/e17_gossip_trust.mjs:422` is a
ternary that always prints —
`const echoVerdict = … ? 'SOURCE_BEATS_ECHO' : 'ECHO_STEALS_TRUST';` — with no
`process.exit`, no assertion, no comparison against the prior committed
`receipts_e17.jsonl`. A repo can commit a result, then change the math, and CI
happily records the **contradiction** as a new finding. Counted across the
repo: **19 of 28 experiments contain a hard-fail exit; 9 do not** (`e16`, `e17`,
`e18`, `e19`, `e20`, `e22`, `e25`, `e41`, `smoke.mjs`, `tools_gauntlet.mjs`).
The ungated ones are exactly the ones making the most interesting claims.

**The receipt gate is a real gate — and it is aimed at the wrong target.**
CI's last step verifies 17 committed chains with `process.exit(bad ? 1 : 0)`.
Mutating the FNV offset basis (`…2325n → …2326n`) turned it properly RED:
`{"ok":false,"at":1,"why":"hash mismatch"}`, **exit 1**. Pristine: 17/17
VERIFIED, exit 0. So the chain verifier fails when it should.

But the chain seals *the rows the experiment wrote*. If the experiment's math
changes, the rows change, the new rows chain correctly, and the gate goes green
— because the gate never re-derives the **previous committed** run. **A
self-consistent chain proves the ledger wasn't tampered with; it cannot prove the
ledger says anything true.** A cross-run check (re-verify yesterday's committed
chain against today's code, or pin a digest like E33's `digest=0xd93adc08`) is
one line and would have caught this.

**Positive control, same repo:** E17's mechanism line is genuinely
informative — `post-300 echo=0.4998 vs source=0.6255` shows the echo free-riding
while it copies, which is a mechanism, not a vibe. Report that part too.

## 2. `thought-amplifier` — a committed competition result where all three entries scored zero because no entry exists

**What it is.** A continuous thought-generation engine: a small model thinks in
a loop, a supervisor adjusts prompt/temperature/interval. Pure-stdlib runtime
(verified: `numpy`/`scipy`/`sklearn`/`llama_cpp` appear **only** under
`experiments/`, never in the core loop — the README's claim holds). 623 test
functions across `tests/`, `router/tests/`, `scheduler/tests/`, CI'd on Python
3.10–3.12.

**The find.** `competition/SPEC.md` specifies a blind judged competition —
three LLMs each implement the same `bottle.py` (HMAC sealing, replay
protection), judged by an independent suite on correctness/elegance/robustness.
`competition/RESULTS.md` is committed with:

```
## kimi — 0.0/100   … MISSING: bottle.py not found
## glm  — 0.0/100   … MISSING: bottle.py not found
## claude — 0.0/100 … MISSING: bottle.py not found
```

`git ls-files competition/` returns **three files**: `RESULTS.md`, `SPEC.md`,
`tests/judge.py`. No `kimi/`, `glm/`, or `claude/` directory is tracked. **The
competition was published as a result with zero competitors, and the document
that says so reads like a completed evaluation.**

**I verified the judge is not the problem.** I wrote a real `bottle.py` to spec
(HMAC-SHA256, `hmac.compare_digest`, JSON-canonical signing) and ran the repo's
own judge against it: **91.0/100 — correctness 30/30, robustness 25/25,
documentation 10/10**, details `['Correctness: 6/6 tests passed', 'Robustness:
4/4 edge cases handled', …]`. The harness discriminates properly; it was handed
nothing. (`RESULTS.md` was rewritten by that run and restored with
`git checkout`; tree is clean.)

**Two smaller drifts in the same repo, in the honest direction:**
- README claims "551 tests (444 · 37 · 70)"; actual is **623 (515 · 38 · 70)**.
  The count grew — the README is stale, the repo improved.
- `scheduler/` and `scheduler/tests/` ship **no `__init__.py`**, so
  `python -m unittest discover` collects **0 tests** from `scheduler/tests` and
  `router/tests` while `pytest` (path-based) finds them all. CI uses pytest, so
  CI is green and the package is still unpackaged. Anyone reproducing with
  stdlib tooling silently loses 108 tests.

## 3. `quilt-cortex` — the fleet's witness idiom hashes UTF-16, so it cannot reproduce the canary

**What it is.** A tri-layer decision spine: TypeSafe JEV (one-pass typed
decisions with calibrated probabilities) → a GLM narrative review bought *only*
by doubt → MOTHquantum for genuine-entropy tie-breaks, with every decision
booked into a hash-chained receipt.

**The smoke test is the best gate in this scout.** `node smoke.mjs` in a clean
clone: **11/11 green, exit 0** — offline, mock-flagged, zero live calls. It
checks gate-band coverage (`gates seen: fast-accept, tie-broken, flagged`),
calibration math, and then **tampers with row 10 to prove the chain verifier can
fail**. I mutation-tested it: breaking the FNV prime
(`0x100000001b3n → …1b4n`) produced `FAIL tamper detected at exact row —
{"ok":true,"links":40}` and **exit 1**; restore returned 11/11 green. This is a
genuine fail-first gate. It is the model the rest of the fleet should copy.

**The defect — and it is inherited, not local.** `cortex/receipts.mjs` hashes
with `s.charCodeAt(i)`, which yields **UTF-16 code units, not UTF-8 bytes**:

```
fleet fnv1a64 (charCodeAt):          0x77ff2029b867f2b5
correct FNV-1a 64 over UTF-8 bytes:  0x24a555471370b18d   ← the canary
```

For pure ASCII the two agree (`FNV-1a("hello") = 0xa430d84680aabd0b` both ways),
which is why it passes every test it has — and `grep -rn '24a5554\|café\|canary'`
returns **nothing** in this repo. So the chain is self-consistent and
cross-repo-incompatible for any non-ASCII state, exactly when a cell's state
carries the Unicode that makes it a cell. `quilt-murmur`'s
`murmur/receipts.mjs` is **byte-identical** (its own comment says "ported
verbatim from … quilt-cortex"), so this is a shared-idiom defect, and
`quilt-murmur` never asserts the canary either. This is the accent trap in
library form: the hash is right for the tests that exist and wrong for the
string that matters.

**A second, sharper gap — a shadow implementation.** `cortex/chord.mjs:86-89`
computes the calibration delta **inline**, duplicating `calibrationDelta()` in
`cortex/typesafe.mjs:203`. `chord.mjs` never imports the tested function.
I sign-flipped the live copy (`(dist-own)` → `(own-dist)`) and **all 11 checks
stayed green**. Probing the booked rows directly shows the real damage:

```
pristine:  {"delta":{"alpha":0.6438,"beta":0.3562},"mae":0.5}
mutated:   {"delta":{"alpha":-0.6438,"beta":-0.3562},"mae":0.5}
```

Every calibration row — the chord's stated "learning signal" — inverted, and
`mae` is **unchanged at 0.5**, so the one field a magnitude-style check would
watch is provably blind to a sign error. The suite's only calibration assertion
on live rows is `r.calib && r.state_hash` — truthiness, never value.

## 4. `dual-band-guard` — a genuinely faithful polyformalism port, and the best prose in the unexamined set (inspected, not executed)

**What it is.** Three *untrainable* guards that classify a surprise as
**correctable** (learn from it) or **irreducible** (preserve, never consume).
Zero learned parameters, zero dependencies, no `unsafe`. The framing is
excellent and unusually precise: *the domestication trap* — a model that learns
from everything eventually loses the capacity to be surprised. It routes
irreducible surprise to a `PreservationLog` that is never turned into training
data. This is a real architectural position, not a vibe, and the refusal is
structural: the guard has no parameters to update.

**Why another agent should care — the port is honest about its reference.** It
ports `elephant/elephant/terrain.py`, and I checked that reference exists
(28,436 bytes) with the matching `docs/terrain-2026-08-17.md`. The Rust
`Deadband` preserves the semantics that are easy to lose in a port:

| semantics | upstream Python | `src/deadband.rs` |
|---|---|---|
| enter | `if movement > self.threshold` (strict) | `if dev > self.enter` (strict) |
| release | `if movement < release` (strict) | `if dev < release` (strict) |
| anchor while quiet | re-anchors every check | re-anchors every check |
| anchor while crossed | frozen | frozen (`cross_exit`) |
| release keyed to | the threshold that *tripped* | `self.cross_exit` frozen at crossing |
| sensor failure | — | non-finite → rings nothing, changes nothing |

The frozen-`cross_exit` detail is the kind of thing ports usually lose, and the
doc comment states *why* ("a later change can never strand the gate open"). The
level-gate-vs-velocity-gate distinction is carried over explicitly, including its
cost ("that is the discipline's price, and it is the safe direction to err").
Tests cover the exact boundaries (`…exactly_enter_does_not_trip`,
`…exactly_release_does_not_release`) — 109 `#[test]` functions, 334 asserts.

**Structurally wrong, two small things:**
- README claims **"118 tests"**; there are **109** `#[test]` + 18 rustdoc fences
  = 127 code blocks. The 118 matches neither figure.
- README claims **"Property-based tests verify: magnitude non-negativity,
  variance non-negativity, entropy range [0,1], window capacity bounds, count
  consistency, ratio unit interval."** There is **no `proptest` and no
  `quickcheck`** — `Cargo.toml` has zero dependencies *by design*
  ("the guard is weightless"). The entropy-range check is a hand-rolled nested
  loop over `n in 2..20 × pos in 0..=n`, which is a decent exhaustive check but
  is not property-based. The claim overstates the method; the coverage is real.
- No canary and no cross-repo hash reference, so it can't participate in the
  fleet's byte-exactness discipline.

**No execution claim.** No `cargo` in this sandbox; per the brief I inspected
rather than claimed a run. The boundary tests are read, not executed.

## 5. Fleet-level: the method that found all four

Every finding above came from the same three questions, and they are cheap:

1. **What is the number compared against?** The receipt chains in `quilt-murmur`
   (18 files, 17 verified) and `quilt-cortex` re-derive against the *previous
   row* — a real comparison. `quilt-murmur`'s CI gate goes RED on a mutated
   basis. Keep these.
2. **Is there a second copy of this math?** `quilt-cortex` tests
   `calibrationDelta()` and ships a different, untested inline copy in the live
   path. **Grep for the function name in the test, then grep for its arithmetic
   in the caller.** A duplicated formula is a test that has silently stopped
   testing the thing that runs.
3. **Does the artifact change when the science changes?** Break the math, not the
   hash. `eta * r → 0` is the mutation that matters: it inverted a 23/24-seed
   result and every experiment stayed green.

Two corrections to carry forward: **rank by tree bytes minus vendored dirs**
(`quilt-arcade` is 22% vendored; API `size` is history), and **compare canary
integers, never text** — `quilt-cortex` and `quilt-murmur` share a `charCodeAt`
FNV that is correct for ASCII and cannot produce `0x24a555471370b18d` at all.

**Positive controls worth copying verbatim:** `quilt-cortex`'s tamper-a-row
smoke test, `quilt-murmur`'s `FAILED to demote the liar (honest)`, and
`dual-band-guard`'s frozen-release-level reasoning.
