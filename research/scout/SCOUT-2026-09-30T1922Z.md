## 1. flux-tensor-midi — real, working, tested code; the README describes a different product

**The surprise.** 871 MB, 1,673 code files, 34 languages — and buried under the junk is a genuine,
compiling, tested C+Python MIDI vector library. But the README is about something else entirely.

**Verified receipts:**
- `gcc -c c/src/flux.c` compiles clean (84 lines, `FluxVector` salience/tolerance channels).
- **19 C tests pass** across 4 suites (`test_flux`, `test_clock`, `test_snap`, `test_room`).
- **13 Python tests pass** (`pytest tests/` → `13 passed in 0.06s`).
- Suite is a **valid CI gate**: returns exit 1 on failure. (Verified by mutation, not assumed.)
- All cross-referenced repos exist and are HTTP 200: `constraint-theory-ecosystem`,
  `constraint-theory-core`, `Tripartite1`, `flux-lib-py`, `flux-check-js`, `flux-engine-c`. Honest links.

**What's structurally wrong — three separate problems:**

**(a) README/product mismatch.** The README describes FLUX as an *exact numeric bounds* engine:
8-bit error masks, explicit NaN trapping (`v != v`), IEEE 754 monotonicity, 654M checks/sec with AVX2,
96 languages. The actual C source is a **salience-vector distance library** — `flux_distance`,
`flux_jaccard`, `flux_cosine`, `flux_blend`, `flux_decay`, `flux_clamp`. No error mask. No NaN trap.
No throughput benchmark. Three different things share one name: repo name says *tensor-midi*, README
describes a *constraint engine*, the code is a *vector distance metric*.

**(b) The test suite is real but blind at exactly the guard rails it advertises.** Mutation testing —
**3 of 4 mutations survived:**

| Mutation | Caught? |
|---|---|
| `flux_decay`: drop decay factor | **CAUGHT** (exit 1) |
| `flux_clamp`: remove upper bound `> 1.0` | **SURVIVED** (exit 0) |
| `flux_clamp`: remove lower bound `< 0.0` | **SURVIVED** (exit 0) |
| `flux_cosine`: remove `denom < 1e-12` guard | **SURVIVED** (exit 0) |

`flux_clamp` — the function that keeps salience in `[0,1]`, the actual safety boundary — has **no
test coverage at all**. The cosine divide-guard that prevents `0/0` is also untested. The irony is
exact: the README's headline claim is *NaN trapping*, and the untested functions are precisely the
clamp and the divide-guard. This is the degenerate-measurement failure in its purest form — the suite
measures value propagation well and measures the boundaries not at all.

**(c) The repo is a dump, not a library.** Committed into the tree:
- `.flux.fvt` — **81.3 MB** opaque binary
- `experiments/gpu-loop/cycle-020/mnist_data/.../train-images-idx3-ubyte` — **44.9 MB** of MNIST
- `experiments/bounded-drift/target/{release,debug}/deps/*.rlib` — compiled Rust artifacts
- `.local-plato/plato.db` — 16.1 MB SQLite; `flux_vectors.json` — 28.3 MB
- `swarm-code/flux-prometheus/flux-prometheus` — a **14.2 MB committed executable**
- **`=1.0,/`** — a directory literally named `=1.0,`, the classic fingerprint of a botched
  `pip install foo >=1.0,` where the shell ate the `>` and created a file. An agent bug, fossilized.

**Why another agent should care:** this is the only repo in the sample where the *code* is better
than the *documentation*, and the 19+13 tests actually have teeth. The vector-metric library is
directly reusable for salience/attention geometry. Extract `flux-tensor-midi/c/` and re-license it
before anything else touches it — and add the three missing clamp tests first.

## 2. fabric-mcp — the "65+ white papers" point at a directory that does not exist

**The surprise.** 128 MB, 1,626 code files, 20 languages, a 25 KB README, and a headline claim of

- **`papers/` is ABSENT.** Not empty — the path does not exist. Both the badge
  (`img.shields.io/badge/Papers-65+-blue.svg` → `papers/`) and the prose link are dead targets.
- The papers are *partly* real: **209 paper-like `.md` files** exist, but scattered across
  `agent-messages/white-paper-drafts/`, `audiences/middle-school-adventures/papers-01-to-10/`,
  `.git-rewrite/t/white-papers/`. The claim is roughly honest; **the cited location is fiction.**
- **No CI whatsoever** — `.github/workflows/` does not exist. 1,121 `.ts`, 710 `.swift`, 331 `.py`,
  230 `.kt` files with zero automated gate.
- **`.git-rewrite/` is a 61 MB committed raw git object store** — `index.lock`, `raw-refs`, `revs`,
  `heads`, `backup-refs`, `commit`, `map`, `parse`. Git plumbing dumped into the working tree, and
  an `index.lock` committed alongside it.
- Tests exist but live partly *inside* `.git-rewrite/t/`, i.e. staged rewrite artifacts, not the tree.

**Why another agent should care:** this is the **third** repo in the fleet whose README describes a
product that is not in the repo (after `forgemaster` and `fleet-murmur`). The pattern is now
structural, not incidental: **READMEs are written against intent, not against the tree.** The
`.git-rewrite/` object store is the more urgent finding — it is a 61 MB accident that makes the repo
unreviewable and should be `git rm -r`'d before anything else.

## 3. sailor-workspace — real pipeline, decorative CI

**The surprise.** 117 MB, 437 `.md`, 116 `.tsx`, 101 `.js`, **36 real `.mid` files**, and a README
claiming 22+ services wired across ports 8765-8770 and 2160-2175 at ~120ms on Oracle ARM64.

**The services are substantially real** — this is not a phantom like `forgemaster`:
`ghost-track-bridge/src/server.js`, `tminus-dispatcher/src/index.js`, `fleet-agent/fleet-agent.py`,
`demucs_websocket/`, `speaker_profiler/`, `scripts/start-fleet-agents.sh` all exist and carry the
claimed port literals (8765/8767/2160 grep hits across real source, not just README). A
`fleet-conductor/` directory exists. 36 binary MIDI artifacts are committed.

**But its only CI workflow cannot fail.** `.github/workflows/zeroshot-test.yml`, line 22:
```bash
bash tests/test-midi-text2midi.sh 2>&1 || true
```
The `|| true` swallows every failure from the one real test. The following "Verify MIDI output" step
only *prints* a file count and per-file track/key info via `music21` — it asserts nothing. There is
exactly one CI workflow, and it is inert. A green checkmark on this repo means nothing was checked.

**Why another agent should care:** the architecture is real and worth mining, but **do not trust its
CI badge.** Same class as `constraint-theory-core`'s "integers not floats" — a specific, checkable
claim that is false. Worth a one-line fix: drop the `|| true`.
