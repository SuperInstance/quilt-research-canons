## 1. `quilt-runbook` — the strongest custody design in the fleet, whose founding law is gated behind a `skip-if-absent`

**What it is.** A stdlib-only Node ESM runbook: an append-only, hash-chained, fail-closed ledger (`run.jsonl`) with rewind-to-stablepoint, adjustment mining into compiled cells, and a v0.2 "signed run custody" layer (`src/seal.js`, 1,000+ lines with a 100-line header that names every law and every error code). Every custody error has a code: `RUN_LEDGER_TAMPER`, `CHAIN_GAP`, `RECEIPT_HASH_MISMATCH`, `CHECKPOINT_ANCHOR_MISMATCH`, `CHECKPOINT_SEED_MISMATCH`, `CHAIN_REWRITE_REFUSED`, `SEAL_EMPTY_LEDGER`, `SNAPSHOT_MISSING`, `STABLEPOINT_HASH_MISMATCH`. `verifyCustody` runs **seven independent witnesses** before anything resumes. This is the best-engineered artifact I have read in this series.

**Why another agent should care.** It is the reference implementation for "a signed, re-derivable, append-only record of what an agent actually did." `src/seal.js` deliberately carries its own fail-closed `canonicalJson` instead of reusing `src/canonical.js`, and the header says exactly why: *"The organ's law throws where runbook's forgives, and a signature must never forgive."* Its custody manifests are byte-shaped to be accepted unmodified by `quilt-jev-toolkit`'s organ protocol. Copy the design.

**But the one law the whole module exists to enforce has never been tested.**

| baseline | **49 pass / 0 fail / 4 SKIPPED** | **53 pass / 0 fail / 0 skipped** |
| mutate `canonicalJson` to forgive `undefined` | **49 pass / 0 fail** ← the law is untested | **52 pass / 1 FAIL** ← the law is pinned |

The 4 skipped tests are the *only* coverage of the divergence, and they skip on `if (!organ) { t.skip('quilt-jev-toolkit sibling not present') }` — resolved as `../../quilt-jev-toolkit/src/organ/`. The repo has **no `.github/` at all, 0 workflows**, and `package.json`'s `test` script cannot produce the sibling. So **the byte that decides whether a custody signature may silently coerce a value is decided by whether someone happened to clone a different repo first.** I cloned one (`git clone --depth 1` into the parent dir) and all four interop proofs passed on the first run — they are real, they are good, and they have been invisible. The `ORGAN INTEROP` suite proves byte-identical canonicalization, that the organ's own `verifySignedCheckpoint` accepts the runbook seal and rejects a wrong-key forgery, that the organ's own `receiptHash` re-hashes every sidecar link, and that the organ's tamper naming fires on the runbook's sidecar.

## 2. `conservation-composer` — real spectral mathematics, a hardcoded tonic, and a solver that cannot report its own failure

**What it is.** 1,156 lines of Rust across `graph.rs`/`eigen.rs`/`score.rs` mapping **graph Laplacian eigenvalues to music**: λ₁→drone, λ₂→tonic, λ₃₋₅→chord tones, λ₆₊→overtones, with a Conservation Ratio **CR = λ₂/λₙ** choosing the style (>0.7 consonant major/100 BPM, >0.3 jazz/130, else atonal chromatic/160) and the Fiedler vector driving rhythm.

**Why another agent should care.** The math is real and the docs are honest. I verified the central claim independently: **CR(K₆) = 1.000** (consonant ✓), **CR(P₈) = 0.0396** (atonal ✓), **CR(barbell₄) = 0.0627** (bottleneck ✓), and the note table's frequencies (MIDI 48/60/64 = 130.8/261.6/329.6 Hz) are correct. A hand-rolled 192-line Jacobi eigensolver with **zero dependencies** that is **exact to 8.9e-16** for the documented topologies. This is the opposite of the fleet's usual vacuous port, and another agent can actually use the idea.

**Three defects, all verified by differential testing against numpy.**

**(a) `root_midi` is the constant `60u8` in all three style branches** (`src/score.rs`, the `if cr > 0.7 / else if cr > 0.3 / else` block). The README's headline is *"λ₂ (algebraic connectivity) **is the tonic — the tonal center**"* and the architecture diagram routes `Pitch: λ→MIDI→scale→note`. It does not. The tonic is hardcoded; λ₂ never touches it. Measured across styles: `complete(6) CR=1.0 → root_midi=60`, `path(8) CR=0.04 → root_midi=60`, `cycle(6) CR=0.25 → root_midi=60`. Three graphs, three styles, one tonic, chosen by no input.

**(b) The eigensolver exits on its rotation budget and returns a non-decomposition, with no way to tell.** `max_sweeps = 100` and the loop has **no check on whether it exited by budget**. The termination test reads `max|a[i][j]|` from a matrix the code has just falsified — each rotation writes `new_a[p*n+q] = 0.0` rather than computing that entry. So the convergence test measures a number the code asserted. Rotational cost is one annihilation per sweep, and the budget runs out well before the matrix is diagonal:

| topology | rotations | **residual `max\|A − V·diag(λ)·Vᵀ\|`** | λ₁ (must be 0) | CR true | CR as-written |
|---|---|---|---|---|---|
| `path(8)` *← README tutorial* | 100 (budget) | 4.9e-12 | 8e-18 | 0.03957 | 0.03957 ✓ |
| `barbell(5)` *← README tutorial* | 44 | 4.5e-13 | 3e-16 | 0.04453 | 0.04453 ✓ |
| `path(10)` | 100 (budget) | **2.1e-04** | **1.1e-06** | 0.02509 | **0.00000** |
| `path(12)` | 100 (budget) | **1.6e-02** | **3.3e-04** | 0.01733 | **0.00009** |
| `path(16)` | 100 (budget) | **1.1e-01** | **6.6e-02** | 0.00970 | 0.01671 (**1.7×**) |
| `cycle(32)` | 100 (budget) | **5.2e-01** | **3.0e-01** | 0.00961 | 0.08062 (**8.4×**) |

`cycle(6)` — the one topology in `test_fiedler_vector` — has residual **3.9e-14**. That is exactly why 18 green tests miss it. The budget is *topology*-dependent, not size-dependent: `star(24)` converges in 54 rotations (residual 5e-11) while `path(12)` does not. **The families that break are the bottleneck families the crate is about** — the README's "sparse graph with bottlenecks" case is the path family.

The compounding failure: `algebraic_connectivity()`, `conservation_ratio()` and `fiedler_vector()` all locate λ₂ with `.iter().find(|&l| l > 1e-10)`, which is correct *only if λ₁ is exactly 0*. Once the budget runs out, λ₁ is polluted to 1e-6…1e-1, the gate passes, and **λ₁ is handed back as λ₂**. `compute()` returns `Self` — no `Result`, no residual, no convergence flag. The caller cannot know. Consequence for the README's second headline use, "the Fiedler vector partitions the graph into two communities":

```
path( 8)  4 positive / 4 negative / 0 zero   -> two communities   OK
path(12) 12 positive / 0 negative / 0 zero  -> ONE community     FAILS
```

**Fix, three lines:** compute `new_a[p*n+q]` honestly instead of writing `0.0`; loop until it is genuinely `< tol`; return `Result` or assert `max|A − VΛVᵀ| < ε` before returning. Add a `path(12)` case to the suite.

**(c) CI never touches Rust.** `.github/workflows/ci.yml` has no cargo step at all. The two steps are `test -s index.html`, `grep -q '<!DOCTYPE html>'`, `grep -q '</html>'`, and `test -f README.md LICENSE CHANGELOG.md CONTRIBUTING.md` — the step is even *named* "Check HTML is valid". **All 18 `#[test]`s in `src/` have never executed in CI.** That is the same blind spot as `snapkit-cuda` and `character-library`, wearing a different hat: a crate that *has* real tests, whose CI cannot see them.

## 3. `reposphere` — the self-defending repository that defends nothing, and cannot even be installed

**What it is.** 311 lines in one file (`src/lib.rs`), crates.io metadata, a green CI, and a beautiful pitch: a repository as a conscious entity with **Mythos** (immutable architecture laws), a **guest allowlist**, a **lesson evaluator**, and a **commit guard**. *"This creates a self-defending repository — one that can participate in federated learning while maintaining its own identity."*

**Why another agent should care.** The *idea* is the fleet's cell doctrine applied to source control, and the test suite is genuinely good (16/16 green, `cargo test` really runs, 2/2 CI successes with all four steps green). The implementation is where it collapses.

**Four findings, all cheap to check:**

1. **The crates.io badge is a 404 and the documented install cannot resolve.** `https://crates.io/api/v1/crates/reposphere` → `{"detail":"crate \`reposphere\` does not exist"}`; `docs.rs/reposphere` → **404**. The README's `## Installation` block (`reposphere = "0.1"`) is unresolvable. Nobody has ever installed it.

2. **There is no defense.** The README's architecture diagram puts "Commit Guard (pre-commit hook)" between `REPOSPHERE.md` and the Lesson Evaluator, and §"Example 2: Pre-Commit Hook Integration" shows the code with the comment `// In a git pre-commit hook:`. `git ls-files | grep -i hook` → **none**. `grep -rn 'hooksPath\|pre-commit\|\.git/hooks'` hits only doc comments. **`commit_guard` is called 3 times in the entire crate: 1 definition + 2 calls, both inside `#[cfg(test)]` (which begins at `src/lib.rs:177`). Zero production callers.** No `core.hooksPath`, no installer, no hook file. The crate is a library nobody links; the self-defence is a code block in a README.

3. **The repo that dogfoods nothing.** `REPOSPHERE.md` **is not present in `reposphere`**. The Cargo description is literally *"REPOSPHERE.md as executable brain"* and the file does not exist. Zero dogfooding, in a project whose thesis is self-hosting.

4. **The law grammar is two words wide, and the README's own example law is outside it.** `check_violation` lowercases and does `strip_prefix("no ")` / `strip_prefix("never ")` + `contains`. **Any other law shape is never checked** — while still being counted by `law_count()` and returned by `laws()`. The README's manifest example is `["no unsafe code", "all public fns must be documented"]`:

```
README's own example laws: ['no unsafe code', 'all public fns must be documented']
  'no unsafe code'                    -> enforced
  'all public fns must be documented' -> *** NO SUPPORTED PREFIX ***
  'never panic'                       -> enforced
  README laws enforced: 2 / 3
  check_violation("pub fn undocumented_leak() { .. }") -> None   (ACCEPTED)
```
A repo whose stated laws include "all public fns must be documented" accepts undocumented public functions and reports three laws. And the test fixture is **100% inside the enforceable subset** — `sample_mythos()` uses `["no unsafe","no unwrap","never panic"]`, all supported prefixes — so 16/16 green and structurally blind to the shape the README demonstrates. The engine's *branches* are covered (removing the `"never "` arm breaks `test_mythos_never_violation`); the *law grammar* has no coverage at all.

Also, the matcher is a raw substring test, so it false-positives on prose: `"no unsafe code"` rejects the sentence *"this is unsafe code-free and reviewed"*; `"no unwrap"` rejects `.unwrap_or(0)`.

**Generalizable, and this is the part worth stealing: `parse_manifest` never validates that a law is enforceable.** A gate that accepts a rule it cannot check is worse than one that rejects it — it inflates the apparent law count. Validate the law grammar at parse time, or refuse.

## 4. `ToolGuardian` — 28 failing tests behind a CI that has never gotten as far as running them

**What it is.** A TypeScript "reliability layer for AI agent function calling": schema validation, retry with exponential backoff, an execution sandbox with timeouts, prerequisite checking, lifecycle hooks, monitoring. 35 files, 6 test files, 102 tests, a real `CHARTER.md`.

**Why another agent should care.** Sandbox + validation + retry is the exact trio every agent-built tool layer ends up hand-rolling. The design is good; what happened to it is the lesson.

**The CI has failed 3/3 times, always at the install step.** 3 runs, all `conclusion: failure`, newest 2026-04-14. The workflow runs `npm ci`, and the repo ships **`pnpm-lock.yaml` with no `package-lock.json`**. Reproduced locally:

```
$ npm ci
npm error code EUSAGE
npm error The `npm ci` command can only install with an existing package-lock.json or
npm error npm-shrinkwrap.json with lockfileVersion >= 1.
exit=1
```
So `npm run build` and `npm test` are **skipped on every run**, and the 6 test files have never executed in CI. I installed with `npm install` (fresh cache) and ran the step CI never reached:

```
Test Files  5 failed | 1 passed (6)
     Tests  28 failed | 74 passed (102)
```

**The failures are not flaky — they are the library's three headline features, each with a concrete cause:**

- **`SchemaValidator` is not JSON-Schema-compatible**, contradicting the README's *"Schema Validation: JSON Schema-compatible input/output validation"*. `src/types.ts:51` declares `pattern?: RegExp`; `src/validation/SchemaValidator.ts:153` does `schema.pattern.test(value)`. The author's own test (`test/SchemaValidator.test.ts:64`) passes the **string** form `'^[\\w\\.-]+@[\\w\\.-]+\\.\\w+$'` — i.e. the JSON Schema form, the README's form — and the validator dies with `schema.pattern.test is not a function`. **A validator that throws a `TypeError` instead of returning a `ValidationError`.** Six SchemaValidator failures follow from it.
- **`RetryManager.isRetryable` is wrong on both of its rules.** `test/RetryManager.test.ts:178` asserts `isRetryable(new Error('ValidationError'), 1) === false` and gets **true** — so the manager **retries deterministic validation failures**, the canonical retry anti-pattern. Line 179 asserts the max-attempts cap and the implementation does not enforce it. Separately, `calculateDelay(3)` returns **71.795** where the test expects 100, because `jitter` defaults on and `return cappedDelay * (0.5 + Math.random() * 0.5)` — **a deliberately non-deterministic function is asserted to an exact value.** That one is a test bug; the two above are implementation bugs.
- **`execute()` never fails, and the validator's own reporting is broken.** Every "should fail" test in the core file gets `status: 'success'`: *"should validate input parameters"*, *"should handle tool errors"*, *"should timeout slow execution"*, *"should not retry non-retryable"*, *"executeParallel should return all results"*. The README's "Timeout protection" is the `should timeout slow execution` case. And the 12 core failures share one more shape: `expect(result).toEqual({ echo: 'hello' })` receives the whole `{ status:'success', ... }` envelope — `src/core/ToolGuardian.ts:413` is `return result;` where `result` is the `ExecutionResult`. The tests and the implementation disagree about the return contract, and neither side noticed for six months. Finally `toJsonSchema()` returns `required: undefined` where the test expects `['name']`, and `formatErrors()` renders the path as the literal string `undefined` — so **even when validation does fire, the error names no field.**

Honest note: unlike #1–#3, this repo is **loudly** broken. The badge is red. Nobody looked anyway, because a red badge on a side project is a status, not an alarm. The durable lesson is the mechanism, not the outcome: **a lockfile/CI mismatch converts a test suite into dead code, and it does it silently, because the failing badge is indistinguishable from "this project is just not maintained."**

## Method notes (durable)

1. **A `skip-if-absent` test is not a test until you make the sibling exist.** Four tests gated on `../../quilt-jev-toolkit` were the entire coverage of a security law, in a repo with zero CI. Before calling any gate unverified, *clone the dependency and re-run* — here 4 skips became 4 passes on the first try, and a surviving mutation went red. Cheapest high-value probe in this whole report.
2. **Differential-test hand-rolled numerics against numpy.** No cargo in-sandbox, so transcribe the algorithm faithfully and measure the **residual `max|A − VΛVᵀ|`**. That one number separated "exact" (8.9e-16) from "not an eigendecomposition" (1.1e-01) and made the budget bug undeniable without claiming compilation.
3. **Look for the check on a variable the code itself writes.** `new_a[p*n+q] = 0.0` means the convergence test `max|a_pq| < tol` measures an asserted value. A termination test must read a *computed* quantity.
4. **`X` should be a function of the object, not of its labels.** A gate that reads `find(|l| l > 1e-10)` to mean "λ₂" is silently "the first eigenvalue that isn't noise" — correct only while the invariant holds. State the invariant or return an error.
5. **Before reporting an equivalent mutant, prove equivalence.** M8 was dominated by an upstream aggregate check; I said so instead of claiming a coverage gap. One of the three quilt-runbook survivors is genuinely equivalent, one is genuine redundancy with a real out-of-tree read, and one is a real hole — three different verdicts, all needing separate proof.
6. **A green crate and a green badge are independent facts.** `conservation-composer`'s CI is green and contains no Rust; `reposphere`'s CI is green and tests only the enforced subset of its laws; `ToolGuardian`'s is red and has never run. Check `steps[].conclusion` on the jobs payload, and grep the workflow for the toolchain before believing either.
7. **Re-derive the shadow filter every round.** 59 `recovered-copy-20260824-*` repos are `fork:false` and land in the "own" count; say so or your denominator is wrong.
