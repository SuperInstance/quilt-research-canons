## 1. `holonomy-consensus` — the benchmark suite that validates nothing, and is never run

**This is the headline. A published "validation report" whose numbers are hardcoded literals, and whose
benchmark code no test ever calls — under 32 consecutive green CI runs.**

The repo sells "no voting, no quorum — just geometry," and `docs/benchmark_results.md` presents a table of
✅ **VALIDATED** claims, ending `*Generated by Oracle1 subagent on 2026-05-05*`. The Rust source refutes it:

**(a) The baselines are literals, not measurements.** `src/benchmarks.rs:45-60`:

```rust
pub fn benchmark_pbft(n_nodes: usize, n_rounds: usize) -> PBFTSummary {
    let start = Instant::now();
    for _ in 0..n_rounds { node.consensus_round(); }
    let wall_time = start.elapsed();
    let throughput = n_rounds as f64 / wall_time.as_secs_f64();
    let avg = 412.0;                       // <-- hardcoded; wall_time never used for latency
```

`wall_time` feeds **only** throughput. The reported `avg_latency_ms` and `max_latency_ms` are the literal
`412.0`. Raft (`0.15`) and CRDT (`0.20`) are the same shape.

**(b) The "412 ms" PBFT baseline sleeps 412 *microseconds*.** `src/benchmarks.rs:29-33`:

```rust
/// PBFT: 4 network rounds × ~100ms each = 400ms + overhead ≈ 412ms
fn consensus_round(&mut self) -> Duration {
    std::thread::sleep(Duration::from_micros(412));   // 0.412 ms, not 412 ms — 1000x off
```

The comment describes milliseconds; the code sleeps microseconds. The 10.8x speedup is 1000x inflated *and*
hardcoded. Raft then reports `avg_latency_ms: 0.15` and `election_overhead_ms: 150.0` **in the same struct** —
self-contradictory by 1000x, and the doc table used the 150.

**(c) The ML baseline is admitted-unmeasured in the source, and reported as a result in the docs.**
`src/benchmarks.rs:~245`:

```rust
ml_accuracy: 0.0, // TODO: run actual ML baseline benchmark (62% was placeholder, never measured)
```

`docs/benchmark_results.md` §7.3 states it plainly too: *"JC1 cuda-emergence: **Simulated from 62% true
positive rate documented in README**"*, then §8.1 reports "100% vs 62% — ✅ **VALIDATED**". The comparator was
read out of another repo's README. `holonomy_false_positive: 0.0` is likewise a literal — you cannot measure an
FPR without ground truth, and none exists.

**(d) "100% detection" counts a deterministic constant.** `holonomy_accuracy` is `holonomy_tp * 100.0` where
`holonomy_tp` counts `EmergenceDetector::detect(n_agents, n_connections, 1)` — a pure function. N trials of the
same call return the same answer. No ground truth is ever compared. 1000 trials @ 1024 agents is 1000 copies of
one number.

**(e) The benchmark suite is never executed. Ever.** The module doc says *"Run with: `cargo test --release --
benchmark_`"* — but:

```
$ grep -rn "benchmark" tests/ | wc -l
0
```

No test in `tests/consensus_tests.rs` (14 tests) or `tests/integration.rs` (23 tests) references any
`benchmark_*` function. CI runs plain `cargo test`. **32/32 CI runs: `success`.** Green CI, and the CI
exercises none of the code that produced the published numbers. Mutation is structurally impossible to detect
here — you cannot turn a suite RED that is never called.

**(f) The repo contradicts its own README, and its source is the honest part.** The source already carries the
correction that the docs omit:

```rust
// NOTE: Holonomy is a geometric consistency CHECK, not BFT consensus.
// The n-1 claim reflects that geometric checks don't depend on node count,
// NOT that it tolerates Byzantine faults in the consensus-theoretic sense.
```

and `src/zhc_gl9.rs` documents that the **3D SO(3) representation the live path still uses**
(`consensus.rs:8` — `pub struct HolonomyMatrix(pub [[f64; 3]; 3])`) **"DESTROYS correlation (r=-0.045) between
holonomy and alignment"** — which is why GL(9) was written. The README's headline table still reads
`| **Zero Holonomy** | **38ms @ 26316 tx/s** | **Any number** |`. The repo contains its own refutation and
the README never mentions it.

Also: `docs/benchmark_results.md` §3.3 claims holonomy needs **1 message**; §5.1 of the same document claims

**Commit trail corroborates the docs-over-code drift:** `a394f966 "docs: professional README with examples,
