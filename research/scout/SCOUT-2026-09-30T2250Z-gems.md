## 1. `fabric-mcp` embeds a byte-verified stale copy of `claw` — every fleet census double-counts `claw`

**★ surprise · structural · NEW**

A prior report caught that `fabric-mcp`'s "65+ white papers" points at a directory that does not
exist. It did not catch what the repo actually contains.

Measured from the git tree (not the API `size` field, not the README):

| | |
|---|---|
| `fabric-mcp` total blobs | 5,239 |
| `.git-rewrite/t/` (scratch) | 3,062 |
| `claw/` subtree | 966 |
| `claw-mobile/` | 348 |
| markdown files | 1,654 |
| files with `mcp` in the path | **7** — of which 4 are `.md` agent messages |

**The duplication, proven by content-addressed blob SHA** (SHA equality is content equality; this is
not a filename or timestamp comparison):

```
fabric-mcp/claw/ subtree:            966 blobs
paths that also exist in `claw`:     104
BYTE-IDENTICAL (matching blob SHA):  103   (99.0%)
paths unique to fabric-mcp/claw:     862
```

`fabric-mcp` is therefore a **stale partial snapshot** of `claw` — 966 blobs against `claw`'s current
7,445 — 99% of the overlap is bit-for-bit the same content. The one divergent file is
`CLAW_ONBOARDING.md`.

**Also duplicated inside `fabric-mcp` itself:**
- A 3,079,762-byte PNG at `claw/apps/ios/screenshots/session-2026-03-07/canvas-cool.png` and again
  at `claw-mobile/packages/ios/screenshots/session-2026-03-07/canvas-cool.png` — **byte-identical**
  (same blob SHA `965e3cb0fa15`).
- 89 of 308 `agent-messages/*.md` are byte-identical duplicates of
  `.git-rewrite/t/agent-messages/*.md`.

**Why another agent should care — the consequence is larger than this repo:**

`claw` is the single largest repo in the fleet (6,089 TS files) and, per the standing brief, hid from
a full day of scouts purely because it does not start with `quilt`. It is now **counted twice** in any
census that sums file counts or code bytes across repos. The 26.67 MB / 2,345 "code files" that make
`fabric-mcp` look like the second-heaviest TypeScript asset in the fleet are **mostly `claw`'s**.

**Structurally wrong:** a dumping ground whose name describes a 2-file subsystem, holding a stale
copy of the fleet's biggest repo, a 3,062-file rewrite scratch directory, 1,654 markdown files, and
3 MB screenshots committed twice. Same defect class as `quilt-i2i`'s duplicated `erlang/`, one order
of magnitude larger, and it is silently inflating fleet-level metrics.

## 2. The fleet's shared CI templates cannot fail on test failures — and the collector reports `0` when it cannot count

**★ surprise · fleet-infrastructure · mechanism NEW**

Prior reports noted that `sunset-ecosystem`'s Security workflow cannot fail. The cause is upstream, in
the reusable templates, and it is not confined to one language.

`SuperInstance/agent-operations/.github/workflows/` ships 11 templates. Four of them run the test suite:

| template | test invocation | `pipefail`? |
|---|---|---|
| `python-ci.yml` | `uv run pytest -q … 2>&1 \| tee test-output.txt` | **absent** |
| `node-ci.yml` | `pnpm test … 2>&1 \| tee test-output.txt \|\| true` | **absent** |
| `rust-ci.yml` | `cargo test --all-features 2>&1 \| tee test-output.txt` | **absent** |
| `go-ci.yml` | `go test -race -count=1 -v ./... 2>&1 \| tee test-output.txt` | **absent** |

GitHub Actions `run:` blocks execute under `bash -e {0}`. **`-e` is not `-o pipefail`.** In a pipeline
the step's exit status is that of the *last* command — `tee`, which succeeds. Demonstrated locally:

```
$ bash -c 'false | tee /dev/null; echo $?'
0                      # step marked PASSED
$ bash -c 'set -o pipefail; false | tee /dev/null; echo $?'
1                      # step marked FAILED
```

**So: a red test suite produces a green check on all four languages.** The only step in
`python-ci.yml` that *can* fail is the coverage threshold — and coverage is computed from whichever
subset of tests actually ran.

**The same template carries a degenerate collector.** Each of the four opens with a count step:

```bash
count=$(uv run pytest --collect-only -q 2>&1 | grep 'tests collected' | awk '{print $1}' || echo "0")
```

If collection dies, or the output format changes, or the suite legitimately collects nothing, this
writes `count=0` and the step succeeds. **Zero is a number, not an error.** A suite that cannot be
collected is reported as a suite with no tests — the exact class of measurement that agrees with
itself. The same `|| echo "0"` appears in the `passed=`/`failed=` extraction two steps later.

**Blast radius, measured honestly:** I sampled **85 repos that have CI** (38 Python/quilt, 18
TypeScript, 18 JavaScript, 18 Rust, 5 Go — largest by size in each language). Exactly **one** consumes
these templates: `sunset-ecosystem`. So this is **not** a fleet-wide outage today. It is a landmine
in the repo whose only commit is *"plans: fleet CI/CD strategy + 10 reusable workflow templates"*
(#3, 2026-08-21), i.e. the artifact explicitly built to be adopted fleet-wide. Unchanged for ~6 weeks;
every future adopter inherits a CI that cannot fail.

**Structurally wrong:** a reusable-CI template whose central guarantee is inverted, plus a
fail-open `|| echo "0"` in the measurement step that feeds its own reporting.

## 3. `sunset-ecosystem`: the 8,729 badge overstates by 917, 44 test modules import 9 modules the repo does not contain, and the suite hangs at 82%

**deepening of a known repo · numbers and mechanism NEW**

A prior report concluded the 8,729-test claim is "honest" and the suite "unrunnable in CI-shape."
I cloned it and ran it. The claim is not reproducible, and the mechanism is specific.

**Measured** (`pytest tests/ --continue-on-collection-errors`, clean Python 3.11, `GIT_SSL_NO_VERIFY`):

| | |
|---|---|
| README badge | **8,729 tests passing** |
| actually collected | **7,812** — **917 fewer than claimed (10.5% short)** |
| collection errors | **44 test modules** |
| completed to ~82% | **6,329 passed · 86 FAILED · 50 skipped · 2 xfail** |
| full run | **does not complete** — hung at 82% for >4 min, killed at a 20-min ceiling |

**The 44 uncollectible modules import 9 internal packages that are simply not in the repository:**

| missing module | test files importing it |
|---|---|
| `sunset.flux_preset_library` | 11 |
| `sunset.plato_bridge` | 8 |
| `sunset.flux_integration` | 6 |
| `sunset.roomgrid_plato_observer` | 4 |
| `sunset.cuda_kernels` | 2 |
| `sunset.flux_ast_compiler` | 2 |
| `sunset.flux_codegen` | 2 |
| `sunset.health_thermal_bridge` | 2 |
| `sunset.unified_memory` | 2 |

Also: `from sunset import Agent` / `Compiler` / `turbovec` — none of which `sunset/__init__.py`
exports — and a test that requires `repos.json`, a data file absent from the tree.

**What makes this interesting rather than merely broken:** `conftest.py` *deliberately* stubs
`turbovec` and `plato_core` (264 lines of hand-written mocks) so that missing third-party deps stop
being fatal. The team clearly understood the failure mode. The nine **internal** modules were simply
missed — and because item 2 means the CI step cannot fail, **nothing has ever reported any of it.**

The repo is otherwise real: 477 test files, 1,049 vendor-filtered code files, 29 modules, five
workflows, a 166 MB tree. This is the largest genuine Python asset in the fleet. The finding is
narrow and specific: the receipt is inflated by 917, nine of its own modules are missing, 86 tests
fail, and the suite hangs — and the badge is the only place any of that is visible, because the badge
is hand-written and the CI is incapable of noticing.

## 4. The `lau-*` math layer's *branded* crates are 9–13 file shells, and the inflation is git history, not a vendored build dir

**structural · measurement mechanism NEW**

333 `lau-*` repos (6.6% of the fleet) have been counted before. What has not been measured is the
**size→substance inversion in the headline math crates**, nor the fact that it works by a *different*
mechanism than the vendored-tree case already on file.

| repo | API `size` | working tree | code files |
|---|---:|---:|---:|
| `lau-noether-agents` | 87,715 KB | 19 blobs | 11 |
| `lau-dynamical-algebra` | 93,847 KB | 19 blobs | 11 |
| `lau-constellation` | 302,785 KB | 21 blobs | 10 (no README at all) |
| `lau-cryptography` | 75,669 KB | 17 blobs | 10 |
| `lau-logic-foundations` | 60,811 KB | 17 blobs | 10 |
| `lau-stochastic-processes` | 67,275 KB | 17 blobs | 9 |
| `lau-construct-integration-v2` | 70,717 KB | 9 blobs | **1** |

`lau-construct-integration-v2` is the cleanest illustration: **70,717 KB reported; the entire
working tree is 84,049 bytes** — one `src/lib.rs` of 53,308 B, a `Cargo.lock`, a `Cargo.toml`, a
README, a LICENSE, an `AGENT.md`, and one workflow file. A repo whose description promises an
integration-test suite for a 320-crate ecosystem contains exactly one source file.

**Two distinct inflation mechanisms, and they need different filters.** The standing vendor-tree rule
catches committed build output (`whisper-sync` 99.1% vendored, `realtime-core` 99.1%,
`substrate-attest-rs` 434 blobs → 1 code file). These `lau-*` crates are a *different* case: their
working trees are tiny and vendor-free (5.3% and 0.0%), and the 60–300 MB lives in **git object
history**. A filter that only strips vendored directories will not touch them. Reporting `size` as
substance is wrong for both, for opposite reasons.

**Unassessed layer:** the aggregation spine — `lau-glue` (*"Gluing 108 mathematical islands into a
continent"*), `lau-ecosystem-unified` (*"bridging 320+ lau-* crates"*), `lau-constellation`,
`lau-functor-network` (*"composing the 320+"*). No prior scout report has examined any of these. The
fleet's most-branded research surface is a set of leaf crates plus a glue layer whose composition
claims have never been checked against the leaves they claim to join.

## 5. Method notes (reusable, not findings)

- **Census cross-validated.** `quilt-atlas` independently reports `total_repos: 5103`,
  `pages_fetched: 52`. My page-to-exhaustion crawl returned 5,103 / 52. They agree exactly — the
  atlas's *count* is right today. Its `pagination_cap: 120` against a true 52 pages means
  `pagination_cap_hit: false` **cannot** detect under-censoring anywhere in a 2.3× band. The flag is
  well-formed and structurally unable to fail in the range it matters.
- **The pollution filter still applies.** 59 `recovered-copy-20260824-*` repos (31 empty) removed
  before ranking; 5,044 clean, 816 forks, 26 empty repos.
- **Two `size` failure modes confirmed distinct** (item 4): committed vendor trees, and git-history
  bloat with a clean small working tree. Any substance metric must handle both.
- **FNV-1a 64 canary** `0x024a555471370b18d` — not re-derived this run; prior runs established it
  is carried by ~0 of the shortlist.
