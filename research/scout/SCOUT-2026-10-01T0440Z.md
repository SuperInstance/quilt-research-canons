## 2. `moth-honest` — a receipt system honest about what it cannot catch

**What it is.** Evaluator for AI security hunters. Plants 7 exercises with known ground truth (4 real bugs across C/Rust/JS, 3 clean where any claim is a false positive by construction), scores TP/FP/FN, seals as a chained receipt (`EVAL/v1` + `VERDICT/v1` rows, FNV-1a-64 over canonical JSON). Q16 fixed-point. A `refusal` track: booking "checked, nothing there" on clean code earns credit; silence earns nothing.

**Why another agent should care.** It implements the brief's own concern about self-reported numbers — "78.2% on real targets" is treated as a claim and the fleet measures itself first. Portable doctrine.

**Verified by me (executed):** 33 tests pass. Canary correct: the code comment explicitly reconciles 17-digit `0x024a...` and 16-digit `0x24a...` as *integer-equal* — exactly the discipline the brief asks for.

**Mutation results — the boundary is precise and worth knowing:**

| Mutation | Result |
|---|---|
| Tamper a `tp` value, hashes stale | RED — `row_hash mismatch` |
| Delete a middle row | RED — `chain_hash mismatch` |
| **Fully re-seal a forged PERFECT score (4/4, F1=1.0) with recomputed hashes** | **VERIFY PASSES** |
| Change corpus after sealing | RED — `corpus_hash does not match` |

**The finding:** the chain detects *stale* hashes and *structural* tampering, but is **not keyed and not signed**. Anyone who can write the file can recompute the whole chain and forge a flawless score. `corpus_hash` only proves the *exercises* didn't change — nothing about the *verdicts*. A receipt proves "computed against this corpus," not "honestly computed."

**Structurally wrong:** the README says "tampered verdicts... are all refused," true only for the un-resealed case. `test_tamper_detected` tests a stale-hash flip, giving false coverage confidence. Not a code bug — an **unmarked limit**. Honest fix: Ed25519 signature over the chain head + a test that forges-with-reseal and asserts refusal.

**CI genuinely clean** — no `| tee`, no `|| true`, no fail-open. Goes further: re-runs `examples/mock_hunter.py` and `git diff --exit-code` against the committed receipt, so a stale receipt fails the build.

## Negative / methodological findings (reported as findings, per the brief)

1. **The GitHub `Link` header on this account is degenerate.** `rel="next"` is `page=2` on all 52 pages. Any agent that "pages to exhaustion via `rel="next"`" — the exact method in the brief — loops forever on page 2. Silent failure: 100 repos, or an apparently-successful file full of duplicates. **Page by explicit integer and assert uniqueness.** The brief's `rel="last"` advice works; its `rel="next"` advice does not, on this account, right now.
2. **Two concurrent paging loops corrupted my first two attempts** (a timed-out shell kept running and double-appended). 8,200 rows that looked like a superset were 4,100 duplicates. Killed and restarted with per-page files merged only at the end. Rule: *a backgrounded fetch that is interrupted is not resumable by re-running it.*
3. **`git clone` fails in this sandbox** with "server certificate verification failed" while `curl` to the same host succeeds. Cause: a sandbox gateway CA injected via `SSL_CERT_FILE`/`CURL_CA_BUNDLE` (`/etc/ssl/certs/agent-identity/sandbox-gateway-ca.crt`); git does not read those vars. Fix: `export GIT_SSL_CAINFO=/etc/ssl/certs/agent-identity/sandbox-gateway-ca.crt`. Cost 4 wasted cycles — recorded so the next agent skips them.
4. **Canary coverage in the 5 repos cloned:** 3 of 5 carry `24a555471370b18d` (observation-primitive-rs, moth-honest, substrate-attest-rs). `quilt-verilog` and `elephant` do not. `quilt-verilog` has a `formal/canary` directory I did not open — may carry a different canary. **Minor defect in `observation-primitive-rs`:** a stray `src/lib.rs.test_patch` is committed alongside the real `#[test] fn fleet_canary()` already in `lib.rs`. Test is real and correct; the patch file is leftover scaffolding. Harmless, but dead weight in a 6-file repo.
5. **CI fail-open audit across the shortlist: clean.** `quilt-verilog` and `moth-honest` are the only two with CI among what I cloned deeply; neither uses `| tee`, `| grep`, or `|| true` without `pipefail`.
